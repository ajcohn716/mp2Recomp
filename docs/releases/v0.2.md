# mp2Recomp v0.2

Windows and Linux x86-64 installers with ROM autodetection, expanded settings,
and experimental multiplayer and debugging improvements.

## Changes

- Reuse verified precompiled open-source runtime libraries from the bundled SDK
  to reduce local build work. Game code is still generated and compiled locally
  from your own ROM.
- Detect supported ROMs beside the installer executable or in the current
  directory, including `.z64`, `.v64`, and `.n64` byte orders. Manual ROM
  selection remains available.
- Organize F1 settings into Input, Audio, Graphics, and Netplay tabs, with
  graphics controls and public IPv4 lookup for Direct TCP hosting.
- Improve Linux Wayland and X11 support, including libdecor plugins and
  keyboard locale and Compose data.
- Add persistent diagnostic logs, F8 recording, replay checkpoints, and a fix
  for Pirate Land borders.
- Add experimental Steamworks rooms using Spacewar App ID 480 for source builds
  supplied with the Steamworks SDK. Packaged installers use Direct TCP netplay.
- Expand installation, multiplayer, debugging, and source-build guides.

## Installation and upgrade

Download `mp2recomp-installer-linux-x86_64.tar.gz` or
`mp2recomp-installer-windows-x86_64.zip`. Extract the whole archive, keeping the
included SDK archive compressed beside the installer executable. Put your
unmodified Mario Party 2 USA ROM beside the executable for automatic detection,
or select it manually. Choose an installation directory and press **Go**.

To upgrade, select your existing installation directory; saves and settings are
preserved. The installer includes the build tools and dependencies needed for
offline installation. A Vulkan-capable graphics driver is required.

No ROM, game assets, or generated game code are distributed. Matching integration
source, SDK dependency packs, and SHA-256 checksums accompany the installers.

## Validation and limits

Release builds run installer validation and packaged CLI/GUI startup checks on
Windows and Linux. SDK builds also verify the open-source runtime libraries;
Linux checks exercise runtime data and Wayland window creation without a ROM.
Fresh consumer builds on both platforms check that the packaged runtime archives
link and pass self-tests without recompiling their dependencies.

This remains an early experimental port. Linux boot through the title screen has
been tested; full boards, minigames, long sessions, Windows game boot, and
Linux/Windows cross-play still need validation. Some title prompt glyphs appear
as blocks. Steam rooms require a separate source build and further cross-account
and cross-network testing.
